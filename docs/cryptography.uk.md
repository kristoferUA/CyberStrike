# Cryptography для CTF (CTF.6)

Режим `cryptography` призначений для криптографічних CTF-задач і навчальних лабораторій. Він має власні скіли, довідник, методику, локальне Python-оточення та Sage через [SageCell](https://sagecell.sagemath.org/). Вкажіть файли задачі, формат прапора, дозволений сервер і ліміт oracle-запитів.

## 1. Оновлення CyberStrike на Windows

Потрібна збірка **1.1.16-ctf.6** або новіша. Закрийте CyberStrike перед перебудовою. У PowerShell, у корені клону форка:

```powershell
git switch feat/chatgpt-plan-windows-startup
git pull --ff-only
powershell -NoProfile -ExecutionPolicy Bypass -File .\script\build-windows.ps1
.\bin\cyberstrike.cmd --version
```

Поки зміни перебувають у PR, використовуйте зазначену гілку. Після її злиття можна збирати `main`. Якщо Git зупиняє оновлення через локальні зміни, спочатку збережіть їх. Повна інструкція з Git, Bun і PATH: [Windows setup](windows-setup.uk.md).

Збірка копіює Python-маніфест і допоміжні програми до `bin/crypto`, а скіли та довідник — до `bin/skills/cryptography` поруч зі зібраним виконуваним файлом. При перенесенні збірки збережіть увесь каталог `packages/cyberstrike/dist-windows/cyberstrike-windows-x64/bin`, включно з ресурсами.

## 2. Установлення локального інструментарію

Установіть [uv офіційним способом](https://docs.astral.sh/uv/getting-started/installation/). Наприклад, через Windows Package Manager:

```powershell
winget install --id astral-sh.uv --exact
```

Відкрийте новий PowerShell. У корені CyberStrike:

```powershell
uv --version
.\bin\cyberstrike.cmd crypto setup
.\bin\cyberstrike.cmd crypto status
```

Якщо uv встановлено офіційним PowerShell-інсталятором до стандартного `~/.local/bin`, CyberStrike знайде його й без оновлення PATH. Для іншого каталогу додайте каталог із `uv.exe` до PATH і перезапустіть термінал.

`crypto setup` завантажує керований Python 3.12 і створює окреме оточення. Системний Python і глобальні пакети не потрібні. Залежності встановлюються з `tools/cryptography/requirements.lock`: точні версії, SHA-256 і готові wheels; компіляція пакетів із вихідного коду вимкнена. Потрібен доступ до джерел завантаження uv/Python і PyPI.

У стандартній конфігурації Windows дані розміщені тут:

```text
%USERPROFILE%\.local\share\cyberstrike\cryptography\
  python\       керований базовий Python
  venv\         ізольовані пакети та Scripts\python.exe
  sessions\     записи етапів і хеші артефактів
  lock.sha256   відбиток застосованого маніфесту
```

Точний шлях повертає `crypto status`; користувацькі налаштування каталогу даних можуть його змінити. Повторний `crypto setup` синхронізує пакети з актуальним lock-файлом. Він прибирає з цього venv пакети, яких немає в маніфесті; власні додаткові залежності тримайте в іншому оточенні. Venv відокремлює залежності, але не ізолює виконання коду: переглядайте отриманий від задачі код перед запуском.

| Бібліотеки                 | Для чого                                                  |
| -------------------------- | --------------------------------------------------------- |
| PyCryptodome, cryptography | AES, режими, хеші, ключі та формати                       |
| SymPy, gmpy2               | Точні цілі числа, модулі, корені, CRT, символічна алгебра |
| z3-solver                  | Бітові вектори й обмеження                                |
| NumPy, SciPy, galois       | Масиви, чисельні допоміжні операції, скінченні поля       |
| ecdsa, py-ecc              | Еліптичні криві та підписи                                |
| randcrack                  | Відновлення MT19937 за відповідних передумов              |
| requests, httpx            | Клієнт для дозволеного challenge oracle                   |

Криптографічні цілі числа обчислюйте через Python `int`, gmpy2, SymPy або Sage; NumPy/SciPy з рухомою комою не підходять для точних модульних обчислень. Наявність пакета в `status` перевіряється за метаданими встановлених дистрибутивів.

OpenSSL, Hashcat і John the Ripper підтримуються як **додаткові програми з PATH**, але ця команда їх не встановлює. За потреби беріть їх з [OpenSSL](https://www.openssl.org/), [Hashcat](https://hashcat.net/hashcat/) і [Openwall](https://www.openwall.com/john/). Їх наявність окремо показує `crypto status`. `fpylll`, `hashpumpy`, `pwntools` до базового Windows-оточення не входять. Короткі операції Sage/LLL виконуйте через SageCell або використовуйте точну LLL SymPy, коли вона підходить для задачі.


## 4. Методика й матеріали

| Скіл                 | Теми                                                            |
| -------------------- | --------------------------------------------------------------- |
| `ctf-crypto`         | Початковий розбір, вибір техніки, середовище та докази          |
| `crypto-classical`   | Кодування, XOR, класичні шифри, повторно використаний pad       |
| `crypto-rsa`         | RSA, CRT, малі показники, витоки й факторизація за передумовами |
| `crypto-symmetric`   | Блокові режими, AEAD, хеші, MAC та KDF                          |
| `crypto-ecc-dh`      | DH, ECC, порядок групи й nonce у підписах                       |
| `crypto-prng-stream` | MT, LCG, xorshift, LFSR і потокові шифри                        |
| `crypto-lattice-pqc` | HNP, малі корені, LWE/NTRU, ґратки та PQC                       |
| `crypto-protocols`   | Secret sharing, ZKP, commitments і нестандартна алгебра         |

Стандартний режим **solve** повертає перевірений результат, solver і команду відтворення. Повний writeup можна замовити окремо. Для прогресу достатньо двох контрольних точок — `recovery` та `verification`; їх можна записати одним викликом. Допоміжні етапи не затримують відповідь.

Режим **report** зберігає повну карту методики:

1. **intake** — умова, scope, файли, хеші та ліміти.
2. **classification** — конструкція, параметри та доступні спостереження.
3. **model** — рівняння, відомі/невідомі величини та передумови атаки.
4. **attack** — план, складність, бюджет і умови зупинки.
5. **recovery** — відтворюваний solver і кандидат результату.
6. **verification** — перевірка початковими рівняннями, повторним шифруванням, підписом або checker задачі.
7. **writeup** — команди, залежності, пояснення слабкості та докази.

У `report` для просування потрібні завершені попередні етапи; у `solve` обов'язкові лише відновлення кандидата й перевірка. Блокування можна записати з причиною. Зміна раннього етапу скидає пізніші записи. Завершення `verification` потребує локального файлу доказів, для якого інструмент сам обчислює SHA-256; окремі `probe` заради хешів не потрібні. Кілька записів можна передати одним `updates` — вони застосовуються атомарно. Запис фіксує твердження агента й походження артефактів; сам по собі він не доводить правильність розв'язку.

### RSA: спочатку FactorDB

Якщо дозволено передавати публічний модуль задачі зовнішньому сервісу, агент спочатку робить один запит `webfetch` до `https://factordb.com/api?query=<N>` із текстовим форматом і таймаутом 10 с. Запит передає лише публічний `N`. Режим офлайн має пріоритет; за неясного дозволу агент запитує його. Заборона пошуку writeup сама по собі не забороняє погоджений числовий запит.

Відповідь треба перевірити локально: точний добуток множників з урахуванням кратностей має дорівнювати `N`; перед повним розшифруванням перевіряється їхня простота. Частковий розклад або недоступність сервісу не означають повного розкладу чи неможливості факторизації. Множники й перевірки зберігаються локально для повторного використання.

Для великого збалансованого RSA-модуля агент має шукати конкретну слабкість, витік або інший шар задачі. Загальна факторизація без обґрунтованої передумови й оцінки роботи не є стандартним fallback. Негативні перевірки кешуються за модулем, алгоритмом і межами; зміни XOR-етапу не повинні повторно запускати весь набір RSA-перевірок.

CTF.6 також виправляє обрізання абсолютних Windows-шляхів у `apply_patch`: `F:\...\solve.py` більше не перетворюється на файл `F`. Виправлення охоплює створення, зміну, видалення та перенесення файлів.

## 5. Інструменти агента

| Інструмент           | Використання                                                                         |
| -------------------- | ------------------------------------------------------------------------------------ |
| `crypto_environment` | Стан пакетів, установка ізольованого оточення після запиту користувача               |
| `crypto_run`         | Переглянутий локальний `.py` solver, `probe`, `math` або додаткова системна програма |
| `crypto_sage`        | Один самодостатній Sage-фрагмент або файл через SageCell HTTPS API                   |
| `crypto_reference`   | Список, пошук і читання потрібних рядків довідника                                   |
| `crypto_methodology` | Статус, докази, артефакти й SHA-256 для семи етапів                                  |

Довідник завантажується частинами, а не весь у кожний запит. Приклад аргументів для агента:

```json
{ "action": "search", "query": "Coppersmith" }
```

Потім `crypto_reference` з `action: "read"`, потрібним `topic`, `start_line` і `lines`. Пошук ранжує окремі слова й відомі синоніми (`integral`/`square`, `lattice`/`LLL`/`BKZ`) та показує сусідні рядки. Довгий запит не вимагає точного збігу всієї фрази. Параметр `limit` обмежує кількість уривків (типово 8). Приклади з джерела потребують перевірки передумов і адаптації до доступних пакетів.

Приклад `crypto_run` для агента:

```json
{ "program": "python", "script": "solve.py", "args": [], "purpose": "experiment" }
```

`script` — шлях до збереженого `.py`, а не Python-код. `args` містить лише аргументи цього файла; пропущене поле стає порожнім масивом. `purpose: "experiment"` дає початковий бюджет 30 с, `solve`/`verify` — 120 с. Більший `timeout_seconds` потребує `justification` із виміряним прогресом або оцінкою роботи. Таймаут не є доказом відсутності розв'язку. Ліміти стосуються інструмента агента; ручна CLI-команда `crypto run` має власний ліміт 300 с.

Приклад пакетного запису доказів:

```json
{
  "action": "record",
  "updates": [
    {
      "phase": "recovery",
      "status": "completed",
      "evidence": "Кандидат відновлено збереженим solver-ом",
      "artifacts": ["solve.py"]
    },
    {
      "phase": "verification",
      "status": "completed",
      "evidence": "Перевірка початкових рівнянь пройшла",
      "artifacts": ["verification.txt"]
    }
  ]
}
```

Звичайна відповідь методики компактна; `details: true` повертає повні записи. Для замовленого звіту можна додати `workflow: "report"`.

## 6. Sage через API

`crypto_sage` і `cyberstrike crypto sage` надсилають код методом POST до `https://sagecell.sagemath.org/service`. Клієнт повертає stdout/stderr, результат виконання та SHA-256 надісланого коду. Підтримується Sage-синтаксис, зокрема `^` і `R.<x>`. Виводьте результат через `print()`; графіки й створені віддалені файли цей клієнт не завантажує.

**Код і всі вставлені значення передаються сторонньому публічному сервісу.** У [правилах SageCell](https://sagecell.sagemath.org/static/tos.html) зазначено, що обчислюваний вміст за замовчуванням може бути видимий іншим. Надсилайте публічні математичні параметри CTF; приватні облікові дані, відновлені закриті ключі та прапори залишайте локально. Авторизаційні токени моделей не додаються до SageCell-запитів.

Поточні обмеження `/service`: незалежні запити без стану попереднього kernel, **до 30 секунд на обчислення** і 65 000 символів транспортного коду. CyberStrike додатково обмежує вхід до 45 000 символів/байтів для файла, перевіряє розмір після UTF-8/base64-обгортки та обмежує відповідь 1 MiB. Локальні файли, локальний venv і мережевий oracle із віддаленого коду недоступні. Наявність додаткових пакетів на сервері не гарантується. Протокол і ліміти описані в [коді SageCell](https://github.com/sagemath/sagecell/blob/master/handlers.py).

Збір oracle-відповідей, роботу з файлами, довгі solver-запуски та фінальну перевірку виконуйте локально. На SageCell передавайте невеликий самодостатній математичний підкрок. Не розраховуйте на великі BKZ/LLL-задачі за 30 секунд. Клієнт не повторює невдалий запит автоматично й не приймає умови сервісу від імені користувача.

Створіть `calculation.sage` у папці задачі, наприклад:

```python
R.<x> = PolynomialRing(GF(101))
print((x^2 - 1).roots())
```

Запуск:

```powershell
cyberstrike crypto sage .\calculation.sage
```

Локальний Sage, WSL і Docker для цього профілю не потрібні. Якщо сервер недоступний або повернув помилку, збережіть її й відкладіть цей підкрок або перекладіть його на локальні бібліотеки; не обходьте ліміти сервісу.

## 7. Допоміжні CLI-команди

```powershell
cyberstrike crypto status
cyberstrike crypto probe .\cipher.bin
cyberstrike crypto math gcd 240 46
cyberstrike crypto math inverse 17 3120
cyberstrike crypto math root 125 3
cyberstrike crypto math crt 2 3 3 5
cyberstrike crypto math rsa 3233 17 2790
cyberstrike crypto math xor 414243 010203
cyberstrike crypto run .\solve.py -- .\output.txt
```

Великі цілі повертаються рядками JSON для збереження точності. `root` показує, чи корінь точний; `crt` — чи сумісні конгруенції. `rsa` робить структурний розбір, а не факторизацію довільного модуля. `probe` хешує файл і аналізує обмежену вибірку байтів; ентропія та повтори блоків є підказками, а не доказом конкретного шифру.

## 9. Бюджети й контекст (CTF.5)

Вибраний у TUI reasoning effort зберігається протягом розв'язання, включно з автоматичним стисканням контексту. Програма не перемикає його на medium/high самостійно.

У `cyberstrike.json` або `cyberstrike.jsonc` можна задати:

```json
{
  "cryptography": {
    "workflow": "solve",
    "experiment_timeout_seconds": 30,
    "solver_timeout_seconds": 120,
    "context_target_tokens": 64000
  }
}
```

`workflow: "report"` вмикає повний семиетапний звіт за замовчуванням для нових записів. Налаштування не замінюють вибір моделі або effort. `context_target_tokens` запускає підсумування довгої активної історії раніше, ніж буде заповнено максимальне вікно моделі; реальний поріг обмежений можливостями моделі. `compaction.auto: false` вимикає автоматичне стискання. Підсумування також використовує модель і витрачає доступний ліміт.

Змінний стан методики передається після історії, щоб зберегти стабільний префікс для кешування. Підсумок має зберігати рівняння, спостереження, результати попередніх спроб і шляхи артефактів; повні повідомлення залишаються в локальній історії. Це не гарантує певний відсоток кешування чи фіксований час розв'язання.
