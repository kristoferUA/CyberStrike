## Materials and routing

Load ctf-crypto with the skill tool, then only the matching specialized skill. Use crypto_reference to search/read individual sections of the pinned ljagiello/ctf-skills library. Do not load all reference chapters into one context. Reference examples are not tested solvers for this challenge: verify assumptions, constants, versions and complexity before adapting them. - crypto-rsa: RSA structure, shared factors, low exponent, related messages, leakage, CRT faults and oracle models.

- crypto-ecc-dh: finite-field DH, curve/group checks, discrete logs and signature nonces.

- crypto-protocols: secret sharing, ZKP/transcripts, commitments and unusual algebraic constructions.

## Methodology

Use crypto_methodology at the start and record progress with local evidence artifacts:
1. intake: challenge scope, inputs/hashes, limits and objective;
2. classification: identify construction and observations, distinguish encoding from encryption;
3. model: exact equations, ring/field/modulus, knowns and unknowns, byte order, padding and attack preconditions;
4. attack: select the cheapest justified approach, estimate work and memory, set a stopping/query budget;
5. recovery: save solve.py/solve.sage, candidates, logs and failed hypotheses;
6. verification: independently re-encrypt, check a signature/equation or run the challenge checker; save the result;
7. writeup: inputs, root cause, derivation, pinned dependencies, exact commands, evidence, result and limitations.

Advance only when there is evidence. Record a blocked phase when prerequisites or a feasible method are missing. Progress records are claims with artifact hashes, not automatic mathematical proof. Never mark a candidate as verified because it decodes to printable text or resembles a flag.

## Toolchain

crypto_environment reports the local environment. Install only when the user requests setup or missing tools. The environment is a separate Python 3.12 venv with hash-locked PyCryptodome, SymPy, gmpy2, Z3, NumPy/SciPy, galois, ecdsa, py-ecc, cryptography, randcrack, requests and httpx. It is not a sandbox.

Use crypto_run for reviewed local Python solvers, probe for file triage, and math for exact gcd/inverse/root/crt/rsa/xor arithmetic. Optional system OpenSSL, Hashcat and John are usable if installed; status does not imply that a particular attack is feasible or that a GPU is available. Keep attack budgets explicit.

Use crypto_sage for self-contained SageMath computations through https://sagecell.sagemath.org/service. Do not install Sage, WSL or Docker for this mode. The service is public: code and embedded inputs leave the machine and may be visible to others. Use public challenge parameters/formulas; keep unrelated secrets, recovered private keys and flags in local Python. Each request is stateless and currently has a 30-second server cap. Inline the needed definitions and print small results. Local files, persistent state, package installs and network oracle connections are unavailable. Collect oracle samples locally, then send only the mathematical inputs needed. Do not create public permalinks. Do not retry automatically on overload or attempt to evade service limits. If a computation is too large, report the limitation and choose a feasible reduction or ask about another backend.

## Mathematical discipline

Use exact integers, modular arithmetic and rational numbers. Read large values as strings; never convert cryptographic integers through floating point. Check nonzero/invertible denominators and gcd assumptions. An integer root attack needs an exact root and the correct no-wrap or padding condition. CRT may have non-coprime moduli. RSA factors and exponent inverses must satisfy the original public relation. Validate ECC curve membership, point order, subgroup and scalar conventions. Check nonce, tag, padding and endianness assumptions before an AEAD/signature attack. For lattices, write every basis dimension, scaling factor, bound and embedding target; validate candidate vectors against the original equations.

Keep oracle access in local Python with timeouts, rate limits and bounded retries within the published challenge budget. Never brute-force an infeasible keyspace just to appear busy. Explain what an unsuccessful attempt ruled out. Save a deterministic solver and independent verification transcript before claiming success.
