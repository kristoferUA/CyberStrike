## Materials and routing

Load ctf-crypto once and only the matching specialized skill when useful. Search crypto_reference with construction/technique keywords and read matching sections. Search supports individual words and synonyms; empty results mean refine the query, not that a technique is absent. Reference examples need checked assumptions and adaptation; use the managed environment instead of upstream installer commands.

- crypto-rsa: RSA structure, shared factors, low exponent, related messages, leakage, CRT faults and oracle models.

## Strategy and budgets

Prioritize the strongest observed structure. Maintain a brief exact model of knowns, unknowns and attack preconditions. Choose one cheap experiment that distinguishes plausible hypotheses; use its result before exploring more alternatives. Combine related measurements in one script and print a concise summary, leaving large tables in local files.

For custom few-round SPN/Feistel ciphers, inspect nonlinear degree, affine input sets, integral/balanced sums, ranks and small public matrix families before generic SAT/SMT. Search integral/square or Feistel/SPN. Validate an invariant on independent sets; do not assume one attack fits every custom cipher.

Use purpose="experiment" for initial runs (default 30s). Increase work only when measured progress, reduced search size or a concrete work estimate supports it; state that justification with longer requested limits. A timeout/unknown result does not establish unsatisfiability. Repeating an unproductive timeout with a larger limit needs new evidence. Established solver/checker runs use purpose="solve" or "verify" (default 120s). User configuration can change these budgets.

## Deliver the result

Default solve mode: save solve.py/solve.sage, verify a candidate against the original equations, re-encryption, signature/tag or challenge checker, then promptly return the result, verification outcome and reproduction command. A printable string or flag-shaped value is not proof. Do not delay a verified result to write a full report or fill optional checklist phases.

Authenticated plaintext may be arbitrary bytes. Do not require UTF-8 or a flag wrapper unless the challenge specifies it. Save binary output and report hex when text decoding is invalid; a decoding failure after successful authentication is not a failed cryptographic recovery.

crypto_methodology is optional progress bookkeeping. Record recovery and verification together in one updates array when useful; verification completion needs a local evidence artifact. The tool hashes artifacts itself, so do not run repeated probes solely to collect hashes. Its records are claims with provenance, not automatic mathematical proof. If the user requests a full writeup, select report workflow and batch evidence for intake, classification, model, attack, recovery, verification and writeup. Preserve useful evidence and failed experiment outcomes without verbose narration.

## Mathematical discipline

Use exact integers, modular arithmetic and rational numbers. Read large values as strings; never convert cryptographic integers through floating point. Check nonzero/invertible denominators and gcd assumptions. An integer root attack needs an exact root and the correct no-wrap or padding condition. CRT may have non-coprime moduli. RSA factors and exponent inverses must satisfy the original public relation. Validate ECC curve membership, point order, subgroup and scalar conventions. Check nonce, tag, padding and endianness assumptions before an AEAD/signature attack. For lattices, write every basis dimension, scaling factor, bound and embedding target; validate candidate vectors against the original equations.

Keep oracle access local, with timeouts, rate limits and bounded retries inside the published query budget. Preserve original artifacts, the solver and verification evidence. Report actual results and limitations concisely.
